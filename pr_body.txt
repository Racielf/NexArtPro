## Root Cause

The Edge Function `issueSigningAccessLink` and the client-side fallback in `nexArtSign.js` generate a raw token, hash it, and attempt to persist the hash to the database using `entities.SigningParticipant.update()` or `SigningPackage.update()`. 

However, both calls had a `.catch(() => {})` appended to them. Because the `update` wrapper throws an Error if the Supabase RPC/query fails (e.g. due to missing RLS, mismatched ID, or temporary DB outage), the `.catch(() => {})` **silently swallowed the persistence failure**. 

As a result:
1. The token hash was **never saved** to the database.
2. The function **continued execution** and returned a 200 OK with the `signing_url` containing the unpersisted token.
3. The email was sent to the client.
4. When the client clicked the link, `resolveSigningPackageToken` checked the DB, found no matching hash, and threw **"Invalid or expired link"**.

---

## Files changed

- `supabase/functions/issueSigningAccessLink/index.ts`
- `src/lib/nexArtSign.js`

## Fixes
- Removed the `.catch(() => {})` silent suppressors from the token persistence `update` calls in both the Edge Function and the client-side fallback.
- If token persistence fails, the function will now throw immediately (caught by the outer `try/catch` in `Deno.serve`) and return a 500 error instead of issuing a phantom token.
